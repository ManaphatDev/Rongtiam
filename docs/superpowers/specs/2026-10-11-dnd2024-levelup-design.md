# เฟส 5b: เลเวลอัพตัวละคร D&D 2024 (เลเวล 2–20)

วันที่ 2026-10-11 · กิ่ง `phase-5b-levelup` (แตกจาก `main` หลัง 5a merge) · สถานะ: ผู้ใช้อนุมัติดีไซน์ในแชตแล้ว รอตรวจเอกสารนี้

## 1. เป้าหมาย

ตัวละคร D&D 2024 ที่มีอยู่ขึ้นเลเวลได้ทีละเลเวลจนถึง 20 ผ่านตัวช่วยที่พาเลือกทุกอย่างที่กติกาบังคับ และสร้างตัวละครใหม่ที่เลเวลสูงได้ด้วยการรันตัวช่วยเดียวกันซ้ำ GM เป็นคนอนุญาตให้ขึ้นเลเวล ผู้เล่นเป็นคนเลือกของในเลเวลนั้น

**เกณฑ์สำเร็จ:**
- ตัวละครทั้ง 12 อาชีพ ขึ้นจากเลเวล 1 ถึง 20 ทีละขั้นได้ในเทสต์ และทุกขั้นผ่าน `parseCharacter` กับ `derive()`
- ผู้เล่นที่ไม่ใช่ GM ขึ้นเลเวลเกินที่ GM อนุญาตไม่ได้ แม้ยิง API ตรง (เทสต์ฐานข้อมูล)
- e2e บน 375×812: GM อนุญาต แล้วขึ้นเลเวล 1→3 จนจบ พร้อมทอย HP
- ชีทเดิมที่ไม่มีฟิลด์ใหม่แสดงค่าเหมือนเดิมทุกตัว

### ที่ผู้ใช้ตัดสินใจแล้ว

1. ขอบเขต: เลเวลอัพ 2–20 **และ** ปุ่ม "เริ่มที่เลเวล N"
2. HP ต่อเลเวล: ผู้เล่นเลือกเองทุกครั้ง ระหว่างค่าเฉลี่ยกับทอย Hit Die
3. เวท: ขั้นเลเวลอัพ **ไม่มี** การเลือกเวท ช่องเวทและจำนวน cantrip/prepared ปรับตามเลเวลเอง (`derive` อ่านตาราง SRD อยู่แล้ว) ผู้เล่นเพิ่มเวทเองในชีท
4. แนวทาง **A**: ตัวช่วยแยก แก้ตัวละครที่มีอยู่ ไม่สร้างใหม่ทับ
5. **GM อนุญาตการขึ้นเลเวล** ผู้เล่นเลือกของในตัวช่วยเอง และบังคับฝั่งเซิร์ฟเวอร์

### สมมติฐาน (แก้ได้ตอนตรวจ)

- อาชีพเดียวตลอด (ไม่มี multiclass)
- ขึ้นเลเวลแล้วย้อนไม่ได้ ถ้าเลือกผิด GM แก้ค่าในชีทด้วยมือ
- ชีทที่สร้างด้วย "สร้างชีทเปล่า" ก็อยู่ใต้กฎเลเวลเดียวกัน (หัวข้อ 8)

## 2. นอกขอบเขต

- multiclass, ลดเลเวล, ย้อนการเลือกของเลเวลที่ผ่านไปแล้ว
- เลือกเวทใหม่ (ตัดสินใจแล้วในหัวข้อ 1) รวมถึงเวทที่ subclass ให้ (เช่น Domain Spells) ซึ่งลงเป็นข้อความฟีเจอร์
- ผลเชิงตัวเลขของฟีเจอร์เกินกว่าที่ `derive.ts` คำนวณอยู่ (Extra Attack, Rage, Sneak Attack ฯลฯ) ลงชีทเป็นข้อความเหมือน 5a
- ตัวนับทรัพยากรอาชีพและปุ่มพักสั้น/ยาว
- XP และ milestone อัตโนมัติ (GM กดอนุญาตเอง)

## 4. ข้อมูล (เพิ่มแบบ additive)

**บนชีท (`D2024Z`):**
- `hpGains: number[]` (ค่าปริยาย `[]`, ยาวไม่เกิน 19, แต่ละค่า 1..12) ผลของ Hit Die ในเลเวล 2, 3, 4… ตามลำดับ ไม่รวม Con
- `levelAllowed: number | null` (ค่าปริยาย `null` แปลว่าเท่ากับ `level`) เลเวลสูงสุดที่ GM อนุญาต

**`derive` คิด HP ใหม่:**
`maxHp = perLevel(hitDie) + Σ_{l=2..level} perLevel(hpGains[l-2] ?? hitDie/2 + 1)` โดย `perLevel(v) = max(1, v + conMod)` เหมือนวันนี้ ชีทที่ไม่มี `hpGains` จึงได้ค่าเท่าเดิมทุกเลเวล `overrides.maxHp` ยังชนะทุกอย่าง

**ห้อง:** `rooms.settings.startLevel` (1..20, ไม่มีค่า = 1) เลเวลสูงสุดที่ผู้เล่นสร้างตัวละครได้ GM ตั้งในส่วนตั้งค่าห้อง (`settings` แก้ได้เฉพาะ GM อยู่แล้ว)

**ประวัติ:** `choices.levels: LevelDraft[]` เก็บร่างของแต่ละเลเวลที่ผ่านมา เป็นข้อมูลอ้างอิงเหมือน `choices.build` ไม่ใช่แหล่งความจริงของค่าบนชีท

## 5. ตรรกะบริสุทธิ์

### 5.1 ขั้นของเลเวลถัดไป (`levelSteps`)

ให้ `L = level + 1` ขั้นที่อาจมี เรียงตามนี้ (มีเฉพาะที่เลเวล L ต้องการ):

| ขั้น | มาจาก | เนื้อหา |
|---|---|---|
| `hp` | ทุกเลเวล | ค่าเฉลี่ย หรือทอย `1d<hitDie>` |
| `subclass` | `ChoicePoint` kind `subclass` (เลเวล 3) | ยืนยัน subclass เดียวที่ SRD มีของอาชีพนั้น |
| `asi` | kind `asi` | (ก) Ability Score Improvement: +2 หนึ่งค่า หรือ +1 สองค่า เพดาน 20 (ข) feat ทั่วไปอื่นที่ผ่าน prerequisite (ใน SRD คือ Grappler: เลเวล 4+, Str หรือ Dex 13+, ได้ +1 Str หรือ Dex เพดาน 20) |
| `boon` | kind `asi` + `epicBoon` (เลเวล 19) | Epic Boon 1 จาก 7 อย่าง + ค่าพลัง +1 หนึ่งค่า เพดาน 30 |
| `class` | kind `expertise` / `fightingStyle` / `metamagic` ที่เลเวล L และจำนวนที่เพิ่มในคอลัมน์ตาราง `Weapon Mastery` / `Eldritch Invocations` | เลือกเพิ่มเฉพาะส่วนที่เพิ่มขึ้น |
| `review` | ทุกเลเวล | ฟีเจอร์ของเลเวล L (อาชีพ + subclass) จาก SRD และสรุปค่าที่เปลี่ยน |

จำนวนที่อ่านจากตารางคือ `table[col][L-1] - table[col][L-2]` ข้อความ prerequisite และ "ability score of your choice" ของ boon แต่ละอันตรวจกับ srd.json ตอนวางแผน

### 5.2 ร่างของหนึ่งเลเวล (`LevelDraft`, zod)

```ts
{
  v: 1, forLevel: number,
  hp: { method: 'average' | 'roll' | null, rolled: number | null },
  asi: { kind: 'scores', plus2: Ability | null, plus1: [Ability | null, Ability | null] }
     | { kind: 'feat', key: string | null, ability: Ability | null } | null,
  boon: { key: string | null, ability: Ability | null } | null,
  expertise: string[], fightingStyle: string | null, metamagic: string[],
  masteries: string[], invocations: string[],
}
```

`forLevel` ผูกร่างกับเลเวลเป้าหมาย ร่างที่ `forLevel !== level + 1` ถูกทิ้งตอนโหลด

### 5.3 `validateLevel(char, draft, srd)` และ `levelUp(char, draft, srd)`

- `validateLevel` คืน issues ติดขั้นแบบเดียวกับ `validate()` ของ 5a ข้อความไทยบอกวิธีแก้ทุกข้อ ตรวจ: วิธี HP และผลทอยอยู่ใน 1..hitDie, ค่าพลังไม่เกินเพดาน, feat ผ่าน prerequisite, Expertise อยู่ในสกิลที่ชำนาญและยังไม่เชี่ยวชาญ, ของที่เลือกไม่ซ้ำของเดิม, จำนวนครบ, `level < 20`, `level + 1 <= levelAllowed` (หรือผู้เรียกเป็น GM)
- `levelUp` throw ถ้ามี issue ไม่เช่นนั้นคืนตัวละครใหม่ที่: `level + 1`, ต่อท้าย `hpGains` (ค่าเฉลี่ยก็เก็บเป็นตัวเลข), บวกค่าพลังใน `abilities`, เพิ่ม `feats` (ASI, Grappler, boon, fighting style), ตั้ง `skills[x] = 2` ของ Expertise, เขียน Weapon Mastery / Invocation / Metamagic ที่เลือกลงข้อความฟีเจอร์ (ชีทไม่มีฟิลด์ของสิ่งเหล่านี้ เหมือน 5a), ตั้ง `subclass` ที่เลเวล 3, ต่อข้อความ `# เลเวล L` ท้าย `features`, ต่อร่างใน `choices.levels`
- `hp.current` เพิ่มเท่ากับ max HP ที่เพิ่ม (ผู้เล่นไม่เสีย HP ที่บาดเจ็บอยู่ และไม่ได้ฟื้นเต็ม)
- ไม่แตะฟิลด์อื่น: ของในกระเป๋า เงิน โน้ต เวท สภาวะ และค่าที่ผู้เล่นแก้เอง

การเขียนลงชีทใช้ `character_patch` แบบ op ต่อฟิลด์ที่เปลี่ยน (diff ระหว่างก่อนและหลัง `levelUp`) ไม่เขียนทับทั้ง `data` เพื่อไม่ชนการแก้พร้อมกันในฟิลด์อื่น

## 6. ตัวช่วยเลเวลอัพ (UI)

- `LevelUp.svelte` โครงเดียวกับ `Builder.svelte`: รายการขั้นด้านบน ปุ่ม ย้อนกลับ/ถัดไป ข้อความ issue ใต้ขั้น และปุ่ม "ยืนยันขึ้นเลเวล L" ในขั้นสรุป
- ขั้น HP ทอยผ่าน `rollDice` และบันทึกผลลงร่างใน `onDecided` ก่อนลูกเต๋าตก (เหมือนการทอยค่าพลังของ 5a) ทอยได้ครั้งเดียวต่อร่าง
- ร่างเก็บใน localStorage คีย์ตาม id ตัวละคร (`persist.ts`) ปิดแผงแล้วเปิดใหม่ทำต่อได้
- `LevelUpPanel.svelte` โฮสต์ตัวช่วย ใช้ `ui.levelUpOpen = characterId` เปิดจากปุ่มบนชีท เมื่อยืนยันแล้วถ้ายังมีเลเวลที่อนุญาตเหลือ ตัวช่วยเริ่มเลเวลถัดไปทันที
- โหลดไม่สำเร็จมีปุ่มปิดและลองใหม่ (แบบเดียวกับ `BuilderPanel` หลัง PR #5)
- ข้อความไทยทั้งหมดรวมไว้ในตารางตรวจคำแปลแบบ 5a

## 7. GM และปุ่ม "เริ่มที่เลเวล N"

**บนชีท:**
- GM เห็นช่อง "เลเวลที่อนุญาต" (ตัวเลข `level`..20) และปุ่ม "+1" ข้างช่องเลเวล
- เจ้าของเห็นป้าย "ขึ้นเลเวลได้ (ถึงเลเวล N)" และปุ่ม "ขึ้นเลเวล" เมื่อ `levelAllowed > level`
- GM เปิดตัวช่วยแทนผู้เล่นได้ทุกเมื่อ ไม่ต้องตั้ง `levelAllowed` ก่อน
- ช่องเลเวลแบบพิมพ์ตัวเลขแก้ได้เฉพาะ GM

**ใน builder:** ขั้นรายละเอียดมีช่อง "เลเวลเริ่มต้น" (1..เพดาน) เพดานคือ `settings.startLevel` สำหรับผู้เล่น และ 20 สำหรับ GM เมื่อสร้างตัวละคร builder ใส่ `levelAllowed = N` ในข้อมูลที่สร้าง แล้วเปิด `LevelUpPanel` ต่อทันทีถ้า N > 1 ไม่มีเอนจินแยก

## 8. กฎฝั่งเซิร์ฟเวอร์

migration ใหม่เพิ่ม trigger `BEFORE INSERT OR UPDATE` บน `characters` (ทำงานเฉพาะ `ruleset = 'dnd2024'`) สำหรับผู้ที่ไม่ใช่ GM ของห้อง:

- **INSERT:** `data.level` ต้องเป็น 1 (หรือไม่มี) และ `data.levelAllowed` ต้องไม่เกิน `rooms.settings.startLevel` (ไม่มีค่า = 1)
- **UPDATE:** `levelAllowed` ต้องเท่าเดิม และ `level` ใหม่ต้องเท่าเดิม หรือเท่ากับ `level เดิม + 1` และไม่เกิน `coalesce(levelAllowed, level เดิม)`
- ผิดกฎ → `raise exception ... using errcode = '42501'` ซึ่ง op queue ถือเป็น error ถาวรและ rollback อยู่แล้ว

GM ไม่ถูกตรวจ RPC ที่เป็น security definer ผ่านได้แบบเดียวกับ `members_guard` (ตรวจ `current_user = 'authenticated'`)

**ผลต่อของเดิม:**
- ชีทเปล่าที่ผู้เล่นเคยพิมพ์เลเวลเอง: ค่าที่มีอยู่ไม่ถูกแตะ แต่ต่อจากนี้ผู้เล่นขึ้นเลเวลได้ผ่าน GM เท่านั้น
- นำเข้าไฟล์ตัวละคร (`transfer.ts`) โดยผู้เล่น: ถ้าเลเวลในไฟล์เกินเพดาน การสร้างถูกปฏิเสธ หน้าจอขึ้นข้อความไทยว่าให้ GM นำเข้าหรือเพิ่มเลเวลเริ่มต้นของห้อง

## 9. การทดสอบ

- **หน่วย:** `levelSteps` ตรงกับ overlay และตารางทุกอาชีพทุกเลเวล (snapshot), `validateLevel` แต่ละกฎ, `levelUp` ไม่แตะฟิลด์นอกรายการ, HP ของ `derive` กับ `hpGains` ว่าง/บางส่วน/เต็ม, เมทริกซ์ 12 อาชีพ × เลเวล 1→20 ด้วยร่างอัตโนมัติ (ต่อยอด `fixtures.ts`)
- **ฐานข้อมูล (PGlite):** ผู้เล่นขึ้น +1 ภายใน `levelAllowed` ได้, ขึ้นเกิน/ข้ามขั้น/ลดเลเวล/แก้ `levelAllowed` ไม่ได้, สร้างเกิน `startLevel` ไม่ได้, GM ทำได้ทุกอย่าง, ruleset อื่นไม่ถูกตรวจ
- **e2e บน `/local` ที่ 375×812:** GM ตั้ง "เลเวลที่อนุญาต" 3 → ขึ้นเลเวล 2 (ทอย HP) → เลเวล 3 (subclass) และ reload กลางการทอย HP แล้วผลไม่เปลี่ยน
- `npm run check` 0 errors

## 10. ความเสี่ยง

- **trigger บนตารางที่ไม่รู้จัก ruleset:** ผูกกับชื่อ `dnd2024` ในฐานข้อมูล ถ้าเปลี่ยน id ต้องแก้ migration
- **ชีทเปล่าเสียความยืดหยุ่น:** ผู้เล่นที่ชินกับการพิมพ์เลเวลเองต้องให้ GM อนุญาต ตั้งใจตามข้อ 5 ของหัวข้อ 1
- **ฟีเจอร์เป็นข้อความ:** `features` มีเพดาน 20 000 ตัวอักษร วัดแล้วกรณีหนักสุดคือ Druid เลเวล 20 ราว 15 600 (เลเวล 1 ≈ 6 080 + เลเวล 2–20 ≈ 9 540) ถ้าผู้เล่นพิมพ์เพิ่มเองจนข้อความของเลเวลใหม่จะเกินเพดาน `levelUp` ต่อท้ายเฉพาะชื่อฟีเจอร์ของเลเวลนั้น (มีเทสต์)
- **prerequisite ของ feat เป็นข้อความ:** ตรวจได้เฉพาะรูปแบบที่ SRD มี (เลเวล, ค่าพลัง) อ่านด้วยตัวอ่านที่มีเทสต์
