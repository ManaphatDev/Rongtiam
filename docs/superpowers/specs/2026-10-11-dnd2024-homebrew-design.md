# เฟส 5c: homebrew ของห้อง D&D 2024

วันที่ 2026-10-11 · กิ่ง `phase-5c-homebrew` (แตกจาก `phase-5b-levelup` เพราะใช้โค้ดเลเวลอัพของ PR #6) · สถานะ: ผู้ใช้อนุมัติดีไซน์ในแชตแล้ว รอตรวจเอกสารนี้

## 1. เป้าหมาย

GM สร้างอาวุธ เกราะ ไอเทม เวท feat เผ่า และฉากหลังของห้องเองได้ และของเหล่านี้โผล่ในทุกที่ที่ใช้ข้อมูล SRD (builder, ตัวช่วยเลเวลอัพ, ชีท) เหมือนเป็นของ SRD พร้อมย้ายไปห้องอื่นด้วยไฟล์

**เกณฑ์สำเร็จ:**
- GM สร้างอาวุธ +1 แล้วผู้เล่นใส่ในชีท ค่าโจมตีและดาเมจบนชีทรวม +1 (e2e)
- สร้างฉากหลัง homebrew แล้วสร้างตัวละครด้วยฉากหลังนั้นใน builder ได้จนจบ (e2e)
- feat และ Epic Boon homebrew ถูกเสนอในตัวช่วยเลเวลอัพตามประเภท และค่าพลังที่เพิ่มถูกตรวจเพดาน (เทสต์หน่วย)
- ส่งออกแล้วนำเข้าในห้องใหม่ได้ของครบ ไฟล์เสียไม่ทำให้อะไรพัง (เทสต์หน่วย)
- ไม่มี migration และผู้เล่นเขียนแถว homebrew ไม่ได้ (เทสต์ฐานข้อมูลบน RLS เดิม)

### ที่ผู้ใช้ตัดสินใจแล้ว

1. ทำ 3 กลุ่ม: ไอเทม/อาวุธ/เกราะ, เวท, feat/เผ่า/ฉากหลัง **ไม่รวม** อาชีพ/subclass
2. อาวุธ/เกราะให้ชีทคำนวณ (รวมโบนัส +0 ถึง +3) ไอเทมอื่นเป็นชื่อ + คำอธิบาย
3. ย้ายข้ามห้องด้วยไฟล์ส่งออก/นำเข้า
4. แนวทาง **A**: 1 แถวต่อ 1 ชิ้นใน `room_content` และชั้นรวม `srdFor(ctx)`
5. ดีไซน์ส่วนที่ 1–3 ในแชต (การเก็บ/การรวม, หน้าจอ, ข้อจำกัด/การทดสอบ)

### สมมติฐาน (แก้ได้ตอนตรวจ)

- homebrew มีเฉพาะห้อง D&D 2024 (ห้องระบบ custom มีตัวแก้เทมเพลตของตัวเองอยู่แล้ว)
- GM หลายคนแก้ชิ้นเดียวกันพร้อมกัน: คนที่บันทึกทีหลังชนะ (upsert ของแถวเดียว)

## 2. นอกขอบเขต

- อาชีพ / subclass homebrew
- ไอเทมที่เพิ่มค่าพลัง เซฟ หรือ AC แบบทั่วไป และระบบ attune (ใช้ "ค่าที่กำหนดเอง" บนชีทแทน)
- ตัวเลือกย่อยของเผ่า homebrew (lineage, เลือกสกิล): เผ่า homebrew ไม่มีขั้นเลือกย่อยใน builder
- คลัง homebrew ผูกกับบัญชี
- แปลข้อความ SRD

## 4. ข้อมูล

**การเก็บ:** 1 ชิ้น = 1 แถว `room_content { kind, key, data }`
- `kind`: `hb-weapon`, `hb-armor`, `hb-item`, `hb-spell`, `hb-feat`, `hb-species`, `hb-background` (ผ่าน check `^[a-z0-9-]{1,40}$` ของตาราง)
- `key`: `hb-<slug>` (`^hb-[a-z0-9-]{1,60}$`) สร้างจากชื่อตอนเพิ่ม และไม่เปลี่ยนเมื่อแก้ชื่อ เพราะชีทอ้างด้วย key
- `data`: ข้อมูลของชิ้นตามรูปข้างล่าง (ไม่ซ้ำ `key` ใน data; ใช้ key ของแถว)

**รูปของแต่ละชนิด** (zod ใน `homebrew/kinds.ts` สร้างจาก zod ของ SRD ตัดฟิลด์ที่ระบบเติมเอง แล้วเพิ่มเพดาน):

| ชนิด | ฟิลด์ | หมายเหตุ |
|---|---|---|
| อาวุธ | `WeaponZ` + `bonus` 0..3 | ข้อความไม่เกิน 80 ตัวอักษร; `damage` ต้องผ่านตัวอ่านลูกเต๋าเดิม (`dice/model.ts`) |
| เกราะ | `ArmorZ` + `bonus` 0..3 | `base` 0..30 |
| ไอเทม | `name` ≤ 80, `desc` ≤ 2000 | ไม่มีผลเชิงตัวเลข |
| เวท | `SpellZ` | `classes` เป็น key อาชีพของ SRD; `desc` ≤ 4000 |
| feat | `FeatZ` + `repeatable: boolean`, `boost: { abilities: Ability[] (≥1), max: 20 \| 30 } \| null` | `type` เป็น `origin` / `general` / `fighting style` / `epic boon` |
| เผ่า | `SpeciesZ` (traits ≤ 12 ข้อ) | ไม่มีขั้นเลือกย่อยใน builder |
| ฉากหลัง | `abilities` 3 ค่าไม่ซ้ำ, `feat` (ชื่อ Origin feat ของ SRD หรือ homebrew), `skills` 2 อย่างไม่ซ้ำ, `tools: ToolGrantZ`, `equipmentOptions`: ชุด A (ของ + ทอง) และชุด B (ทองเท่านั้น) | `tool`/`equipment` (ข้อความ) สร้างจากฟิลด์ที่มีโครงสร้าง |

จำนวนต่อชนิดไม่เกิน 200 ชิ้น (เกินแล้ว GM เพิ่มไม่ได้ และ `srdFor` ใช้ 200 ชิ้นแรกตาม key)

**SRD:** `WeaponZ.bonus` / `ArmorZ.bonus` เป็น `default(0)`, `FeatZ.repeatable` / `FeatZ.boost` เป็น optional ข้อมูล SRD เดิมจึง parse ได้โดยไม่ build ใหม่ `boostOf(f)` และ `repeatable(f)` อ่านฟิลด์ก่อน แล้วค่อยแกะข้อความ SRD เหมือนเดิม (ปรับจากที่คุยในแชตว่าจะสร้างฟิลด์ตอน build: วิธีนี้ได้ผลเท่ากันและไม่ต้องแตะ build script)

## 5. `srdFor(ctx)`

- อ่านแถว `ctx.content` ที่ `kind` ขึ้นต้นด้วย `hb-` ตรวจด้วย zod ของชนิด แถวที่ผ่านแปลงเป็นรูป SRD (ใส่ `key` ของแถว) ต่อท้ายรายการของชนิดนั้น
- แถวที่ไม่ผ่านถูกข้าม และคืนรายการ `{ kind, key, issues }` ให้แผง GM แสดงป้าย "ข้อมูลเสีย"
- cache ตามตัวตนของ object `data` ของแถว hb-* ทั้งชุด (แถวถูกแทนที่ ไม่ถูกแก้ในที่ เมื่อ content เปลี่ยน) เพราะ `host.ctx` สร้างอาร์เรย์ใหม่ทุกครั้งที่ถูกอ่าน cache ตามอาร์เรย์จึงใช้ไม่ได้ (แบบเดียวกับ `roomSkillsOf`) ห้องที่ไม่มี homebrew ได้ SRD ตัวเดิม
- ทุกจุดที่เรียก `getSrd()` ตรงๆ (builder, ตัวช่วยเลเวลอัพ, ชีท, `index.ts`) เปลี่ยนมาใช้ `srdFor(ctx)` `getSrd()` ยังอยู่สำหรับโหลดข้อมูลฐาน

## 6. หน้าจอ

**แผง GM "Homebrew"** (`HomebrewEditor.svelte`, `overlay-ui`, `ui.homebrewOpen`)
- เปิดจากปุ่ม "จัดการ homebrew" ในแท็บตัวละคร เฉพาะ GM ในห้อง dnd2024
- แท็บตามชนิด แต่ละแท็บมีรายการ (ชื่อ, ป้าย "ข้อมูลเสีย" ถ้ามี), "เพิ่ม", แก้ไข, ลบ
- ฟอร์มตรวจด้วย zod ตัวเดียวกับตอนอ่าน ข้อความผิดภาษาไทยอยู่ข้างช่องที่ผิดและบอกวิธีแก้ "บันทึก" กดได้เมื่อไม่มีข้อผิดพลาด บันทึกผ่าน `store.saveContent(kind, key, data)` ลบผ่าน `store.deleteContent(id)`
- ลบใช้ `TwoStepButton` และบอกจำนวนตัวละครในห้องที่ใช้ key นี้ (`usage.ts`)
- ส่งออก: ไฟล์ `tabletop-homebrew` `{ format, ruleset: 'dnd2024', schemaVersion: 1, items: [{ kind, key, data }] }`
- นำเข้า: อ่านไฟล์ (≤ 1 MB) ตรวจทุกชิ้น สรุป "เพิ่ม … · แทนที่ … (key ซ้ำ) · ข้าม … (ข้อมูลเสีย)" ให้ GM ยืนยันก่อนเขียน

**ทุกที่ที่ใช้ SRD:** ของ homebrew อยู่ในรายการเดียวกับของ SRD และมีป้าย "homebrew" ต่อท้ายชื่อ
- builder: เผ่า, ฉากหลัง, Origin feat, Fighting Style, Weapon Mastery, เวท
- ตัวช่วยเลเวลอัพ: feat ของ ASI, Epic Boon, Fighting Style, Weapon Mastery
- ชีท: เพิ่มอาวุธ/เกราะ/เวท/feat; ปุ่ม "เพิ่มจากรายการของห้อง" เพิ่มไอเทมลงกระเป๋า (ชื่อ + คำอธิบายเป็นโน้ต ≤ 200 ตัวอักษร)

**ของที่ถูกลบ:** ชีทเก็บ key ไว้ แสดง "ไม่พบ (ถูกลบจาก homebrew)" `derive` ไม่คิดค่า (อาวุธไม่อยู่ในรายการโจมตี เกราะคิดเหมือนไม่ได้ใส่) ผู้เล่นเอาออกเองได้
**ของที่ถูกแก้:** ทุกชีทเห็นค่าใหม่ทันที (อ้างด้วย key)

## 7. ความปลอดภัยและขีดจำกัด

- เขียนได้เฉพาะ GM ตาม RLS เดิม (`content_write`) ผู้เล่นอ่านได้อย่างเดียว ไม่มี migration
- ทุกแถว parse ด้วย zod ทุกครั้งที่อ่าน แถวเสียไม่ทำให้ชีท builder หรือตัวช่วยพัง
- ไฟล์นำเข้าถือเป็นข้อมูลไม่น่าเชื่อถือ: จำกัดขนาด, ตรวจทุกชิ้น, key ต้องตรงรูป `hb-…`, kind ต้องอยู่ในรายการ
- ข้อความของ GM แสดงเป็นข้อความธรรมดาเสมอ (ไม่ใช้ `{@html}`)

## 8. การทดสอบ

- **หน่วย:** zod ของแต่ละชนิด (ค่าขอบ, ข้อความยาว, key ผิดรูป); `srdFor` (รวม, cache, แถวเสีย, เพดาน 200); `derive` (โบนัสอาวุธ/เกราะ, key ที่หาไม่เจอ); builder `validate`/`build` กับเผ่าและฉากหลัง homebrew (เพิ่มเคส homebrew ในเมทริกซ์); ตัวช่วยเลเวลอัพเสนอ feat/boon homebrew และ `boostOf`; ไฟล์ (ไปกลับ, แทนที่, ข้าม, ไฟล์เสีย, เกินขนาด); `usage.ts`
- **ฐานข้อมูล (PGlite):** ผู้เล่นเขียน/ลบแถว `hb-*` ไม่ได้, GM ได้
- **e2e บน `/local` ที่ 375×812:** อาวุธ +1 → ชีทรวม +1; ฉากหลัง homebrew → builder จนจบ
- `npm run check` 0 errors

## 9. ความเสี่ยง

- **กิ่งซ้อน:** 5c แตกจาก 5b (PR #6) ถ้า #6 ถูกแก้ก่อน merge ต้อง rebase 5c
- **ข้อมูลเผ่า homebrew ไม่มีขั้นเลือกย่อย:** builder ต้องรับเผ่าที่ไม่มี `SPECIES_RULES` ได้ (วันนี้ `fixtures.ts` และบางขั้นสมมติว่ามีเสมอ)
- **key ชนกับ SRD:** ป้องกันด้วยคำนำหน้า `hb-` ซึ่ง SRD ไม่มี (ตรวจในเทสต์)
- **ขนาด content ของห้อง:** 7 ชนิด × 200 ชิ้นอยู่ใน `room_snapshot` ทุกครั้งที่เข้าห้อง ข้อความยาวถูกจำกัดในแต่ละช่องแล้ว
